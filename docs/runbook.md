How to set up, run, build, test, release and fix this project. Commands assume macOS (Apple Silicon) and the repository root unless stated.
Paths below use `$REPO` for the repository root (the folder containing `package.json` and `docs/`).

## 1. Prerequisites

| Need | For | Version / note |
|---|---|---|
| Node.js + npm | everything | Node 22 LTS recommended; 20.17+ works. Node 26 pre-release works but npm warns |
| Google Chrome | e2e tests, browser testing | any recent; path used by `e2e/cdp.mjs` is configurable (`CHROME`) |
| Xcode | iOS | tested with Xcode 27.1 (iOS 27.1 SDK). Needs an **iOS Simulator runtime** (large download) |
| JDK 21 | Android | `brew install openjdk@21` (no admin rights needed) |
| Android SDK | Android | platform 36, build-tools 36.0.0, platform-tools. Command-line tools are enough, Android Studio is optional |
| ffmpeg | demo videos only | `brew install ffmpeg` |

Xcode note: if `xcode-select -p` prints `/Library/Developer/CommandLineTools`, either run `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer` once, or prefix commands with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` as the scripts do.

## 2. First-time setup

```sh
git clone https://github.com/faraz-fatahnaie/chaharbarg-mobile-app.git
cd chaharbarg-mobile-app
git checkout worktree-v1-offline-game      # until it is merged to main
npm install
npm test                                    # expect: 36 engine + 20 app tests pass
```

Android only (one-time):

```sh
brew install openjdk@21
brew install --cask android-commandlinetools
export JAVA_HOME=/opt/homebrew/opt/openjdk@21
SDK=/opt/homebrew/share/android-commandlinetools
yes | $SDK/cmdline-tools/latest/bin/sdkmanager --licenses
$SDK/cmdline-tools/latest/bin/sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0"
```

(The `temurin@21` cask also works but its installer asks for an admin password; the `openjdk@21` formula does not.)

## 3. Run in a browser (fastest loop)

```sh
npm run dev
```

- Open http://localhost:5173. Use Chrome DevTools device mode (iPhone size, portrait) for the intended layout.
- On a phone on the same Wi-Fi, open `http://<your-mac-ip>:5173` (find it with `ipconfig getifaddr en0`). In Safari use Share → Add to Home Screen to try the PWA.
- Append `?fast` to the URL to make bots move almost instantly.
- Production bundle: `npm run build -w @chaharbarg/mobile` then `npm run preview -w @chaharbarg/mobile` (port 4173).

## 4. Run on iOS

The iOS project is generated by Capacitor in `apps/mobile/ios/` and wraps `apps/mobile/dist`.

### 4a. In Xcode (to see and tap the app)

```sh
npm run cap:sync -w @chaharbarg/mobile      # build web + copy into ios/ and android/
open apps/mobile/ios/App/App.xcodeproj
```

1. Pick a Simulator device from the device menu (on the iOS 27.1 runtime this machine had, the only device was **iPhone Duo**).
2. Press **Run** (⌘R).

### 4b. From Terminal (headless)

```sh
npm run ios:sim -w @chaharbarg/mobile
```

Builds, installs and launches on the first available iPhone simulator and saves a screenshot to `apps/mobile/build/ios/launch.png`. It uses `--display=1`: **on multi-display devices such as iPhone Duo, the default screenshot display is black.**

### 4c. As a Mac app ("My Mac (Designed for iPhone)")

Needs signing: Xcode → Settings → Accounts → add your Apple ID; then App target → **Signing & Capabilities** → *Automatically manage signing* → choose your team; destination **My Mac (Designed for iPhone)**; Run. Without a development certificate the build fails with *"Ad Hoc code signing is not allowed"*.

### 4d. On a physical iPhone

Same signing step (a free Apple ID gives a 7-day certificate), connect the phone, select it as the destination, Run. Note that distribution to users in Iran cannot rely on the App Store; see [research.md](research.md) §1.

## 5. Build and run on Android

```sh
npm run android:apk -w @chaharbarg/mobile
# → apps/mobile/android/app/build/outputs/apk/debug/app-debug.apk   (≈4.4 MB)
```

The script builds web, syncs, writes `android/local.properties` (`sdk.dir=...`, git-ignored) and runs Gradle with `JAVA_HOME` and `ANDROID_HOME` defaulting to the Homebrew locations. Override them if yours differ. The first build downloads Gradle 8.14.3 and dependencies (~5 minutes).

Install on a phone (USB debugging on):

```sh
/opt/homebrew/share/android-commandlinetools/platform-tools/adb install -r path/to/app-debug.apk
```

Or copy the APK to the phone and open it. Emulator: install a system image (list them with `sdkmanager --list | grep system-images`; on Apple Silicon use an `arm64-v8a` one such as `system-images;android-36-ext18;google_apis;arm64-v8a`, about 1.5 GB) and create an AVD with `avdmanager`; not done yet in this project. Open the project in Android Studio with `npx cap open android` if you prefer the IDE.

Debug APKs are signed with the debug key only. For release see [§9](#9-release-checklist).

## 6. Testing

```sh
npm test                                         # everything (vitest)
npm test -w @chaharbarg/engine                   # rules engine, 36 tests
npm test -w @chaharbarg/mobile                   # economy and ledger, 20 tests
npm run typecheck -w @chaharbarg/mobile          # types
```

What the tests guard (see [rules-spec.md](rules-spec.md) §8 for the full list T1–T32):
capture generation for numerics, Queen/King, Jack · compulsory capture · sur rules (Jack, last round, 50-point cap, Sur Sarbaz) · deal sizes for 2/3/4 players · card conservation and exactly 20 base points over random self-play · clubs scoring (7–6 split, 3-player tie, 4-player teams) · match target · bots return only legal moves · bot levels are ordered by strength · ledger tamper detection and rollback · idempotent purchases, ad cooldown and cap, daily streaks, challenges, payouts.

### UI end-to-end (headless Chrome, no extra dependencies)

Terminal 1: `npm run dev`. Terminal 2, from `apps/mobile`:

```sh
node e2e/cdp.mjs smoke                       # plays a full 2-player match with random moves
PLAYERS=4 node e2e/cdp.mjs smoke             # 4 players (teams)
PLAYERS=3 MODE=pnp node e2e/cdp.mjs smoke    # 3-player pass-and-play
node e2e/cdp.mjs tabs                        # screenshots of Shop / Stats / Settings / tutorial
URL=http://127.0.0.1:4173/ node e2e/cdp.mjs offline   # service worker + "contacts no other host" check on the preview build
```

Environment variables: `URL` (default `http://127.0.0.1:5173/`), `CHROME` (Chrome binary), `OUT` (screenshot folder, default `$TMPDIR/chaharbarg-shots`), `PLAYERS` (2|3|4), `MODE` (`bots`|`pnp`), `TAG` (screenshot prefix).
A run passes when it prints `console errors: []` and reaches the result screen. Smoke runs take 10–150 s depending on the mode.

## 7. Test hooks: `?fast` and the autopilot

- **`?fast`** (URL query): bots think for 20 ms instead of ~1 s. Harmless in production; it is also enabled automatically in autopilot builds.
- **Autopilot** (`src/lib/autopilot.ts`): compiled in **only** when the build sets `VITE_AUTOPILOT`. It clicks the real UI with random choices, tours the tabs, and prints progress in an overlay at the top of the screen plus `AUTOPILOT_STATUS …` lines on the console.
  Spec format: `<players>:<bots|pnp>[:slow]`, e.g. `2:bots`, `4:bots`, `3:pnp`. `:slow` paces it like a person and tours the whole app first (use it for recordings).

```sh
# headless Chrome check
cd apps/mobile
VITE_AUTOPILOT=2:bots npm run build
npx vite preview --port 4173 &
URL=http://127.0.0.1:4173/ node e2e/cdp.mjs autopilot      # prints "DONE ✔ … errors 0"

# native iOS run
VITE_AUTOPILOT=2:bots:slow npm run build
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer npx cap sync ios
# rebuild and run from Xcode (or: sh scripts/ios-sim.sh does the sync itself, but it rebuilds web WITHOUT the hook)
```

**Always rebuild without `VITE_AUTOPILOT` and re-sync before shipping** (`npm run cap:sync -w @chaharbarg/mobile`). Verify with `grep -c AUTOPILOT apps/mobile/dist/assets/*.js` (must print `0`).

## 8. Recording a demo video

```sh
# 1. build + install the :slow autopilot build in the simulator (see §7), then
xcrun simctl io <DEVICE_ID> recordVideo --codec=h264 --display=1 --force raw.mov &   # leave running
xcrun simctl launch <DEVICE_ID> app.chaharbarg.game
# 2. when the overlay says DONE, stop the recording with Ctrl-C / SIGINT (this finalises the file)
pkill -INT -f "simctl io .* recordVideo"
# 3. optional compression (58 MB → under 1 MB)
ffmpeg -i raw.mov -vf "fps=15,scale=540:-2" -c:v libx264 -preset slow -crf 30 -pix_fmt yuv420p -movflags +faststart -an demo.mp4
```

While recording, the raw data goes to a temporary `raw.mov.sb-…` file next to the output; the final file appears at 0 bytes until you stop. Find the device ID with `xcrun simctl list devices`. Raw recordings are large; keep them out of git (GitHub warns above 50 MB; use Git LFS if you need them in the repo).

## 9. Release checklist

**Before any store submission**
- [ ] Read Cafe Bazaar and Myket publisher policies (card games, virtual currency, age rating). Not verified; see [research.md](research.md) §5.
- [ ] Decide on ESRA age-rating registration (unverified for mobile).
- [ ] Replace the mock `AdProvider` / `StoreProvider` ([§10](#10-wiring-real-ads-and-payments)). Mock purchases must not ship as real.
- [ ] Tune the economy with playtests (`data/arenas.ts`, `economy/economy.ts`, `GOHAR_PACKS` prices are placeholders).
- [ ] Build **without** `VITE_AUTOPILOT`; `grep -c AUTOPILOT apps/mobile/dist/assets/*.js` → `0`.
- [ ] **Bump the service-worker cache name** in `apps/mobile/public/sw.js` (`CACHE = 'chaharbarg-v1'` → `v2`, …). The worker is cache-first, so without a bump PWA users keep the old version.
- [ ] Bump `versionCode` / `versionName` (`apps/mobile/android/app/build.gradle`) and the iOS version/build number in Xcode.
- [ ] Change the app id if needed: `appId` in `capacitor.config.json` (currently `app.chaharbarg.game`), then re-run `npx cap sync`. Changing it after publishing creates a new app.
- [ ] Add real app icons and splash screens (current icon is a simple SVG stand-in; native icon sets are Capacitor defaults).
- [ ] Run `npm test`, the e2e smoke in 2p/3p/4p/pnp, and a manual playthrough on a real low-end Android phone.

**Android release build**
1. Create a keystore once and **back it up**: `keytool -genkeypair -v -keystore chaharbarg.jks -alias chaharbarg -keyalg RSA -keysize 2048 -validity 10000`. Never commit it. Losing it means you cannot update the app.
2. Configure signing in `android/app/build.gradle` (`signingConfigs`) from environment variables or `~/.gradle/gradle.properties`, not from files in the repo.
3. `cd apps/mobile/android && JAVA_HOME=/opt/homebrew/opt/openjdk@21 ./gradlew assembleRelease` (APK for Bazaar/Myket) or `bundleRelease` (AAB if a store wants it).
4. Verify with `apksigner verify --print-certs app-release.apk` and install on a clean device.

**iOS**: archive in Xcode with a signing team; distribution channel for Iran is PWA or third-party stores (see research.md). Not done here.

**Web/PWA**: `npm run build -w @chaharbarg/mobile`, upload `apps/mobile/dist` to any static host (HTTPS required for the service worker). `base` is `./`, so it works under any path.

## 10. Wiring real ads and payments

Both are behind interfaces in `apps/mobile/src/lib/services.ts`, so no screen changes are needed.

**Ads** (`AdProvider.showRewarded(placement)` → resolves `true` only when the viewer finished the ad)
1. Pick a network reachable from Iran (Tapsell, Adivery; see research.md §3). Create the account and zone IDs.
2. Add a Capacitor/Cordova plugin or write a small native plugin, then implement `AdProvider` with it.
3. Rewards are granted by `grantAd` in `economy.ts` (cooldown 120 s, 8 per day). Keep ads on Home and Result only. **Never show an ad during a hand.**

**Purchases** (`StoreProvider.purchase(sku)` / `restore()`)
1. Cafe Bazaar: Poolakey (try `capacitor-poolakey`; check it supports Capacitor 8). Myket: its billing library (no Capacitor plugin found; may need a small native plugin).
2. Create the in-app products with the SKUs in `GOHAR_PACKS` (`gohar_20`, `gohar_60`, `gohar_150`) as **consumables** in each store's panel.
3. **Verify the store's RSA signature before** calling `grantPurchase(profile, sku, token, now)`. It is idempotent per token, so replays and restores never double-grant.
4. Delete the mock `registerPayUI` modal path from `App.tsx` (or hide it) in release builds and remove the demo-checkout warning text in `Shop.tsx`.
5. Real money payments need a Shaparak-licensed gateway for the web build; get legal/accounting advice first.

## 11. Common changes (recipes)

| Change | Where |
|---|---|
| Rule toggle default (target score, sur cap, forced capture, opening Jack, Sur Sarbaz points) | `DEFAULT_RULES` in `packages/engine/src/deal.ts`; user-facing defaults in `DEFAULT_SETTINGS` in `apps/mobile/src/economy/economy.ts`; mapped in `src/lib/match.ts` |
| A new rule | engine first, with a test in `packages/engine/test/engine.test.ts`, then document in `docs/rules-spec.md` |
| Add an arena | add an entry to `ARENAS` in `src/data/arenas.ts` (fee and trophy gate must increase: a test enforces it) and a scene function in `src/art/Scene.tsx` keyed by the same `id` |
| Add a bot persona | `BOTS` in `src/data/bots.ts`, then reference its id in an arena's `botPool` |
| Change bot strength | `packages/engine/src/bot.ts`; `bot-strength.test.ts` must still show hard > medium > easy |
| Add a cosmetic | `COSMETICS` (+ `BACK_STYLES` / `TABLE_COLORS`) in `src/data/cosmetics.ts`; deck styles are CSS classes (`.deck-…`) in `styles.css` |
| Change fees, payouts, rewards, ad limits | constants at the top of `src/economy/economy.ts`; update `economy.test.ts` expectations |
| Add a language string | `tr(fa, en)` inline where used; no catalog |
| New achievement | `ACHIEVEMENTS` in `economy.ts` + names in `src/data/achievements.ts` |

After any change: `npm test`, `npm run typecheck -w @chaharbarg/mobile`, `node e2e/cdp.mjs smoke`.

## 12. Data, storage and reset

Browser/WebView `localStorage` keys:

| Key | Contents |
|---|---|
| `chaharbarg.profile.v1` | profile: balances, trophies, XP, stats, owned items, settings, daily state, last 40 ledger entries |
| `chaharbarg.match.v1` | the match in progress (resume) |
| `chaharbarg.mockstore` | mock purchase tokens (demo store only) |

Service-worker cache: `chaharbarg-v1`.

Reset: Settings → *Erase all data*. In a browser: DevTools → Application → Clear storage. In a headless test: `localStorage.clear()` and unregister the service worker (the `autopilot` scenario does this). In the iOS Simulator: `xcrun simctl uninstall <DEVICE_ID> app.chaharbarg.game`.

If the stored balance or ledger is edited by hand, the next load rolls back to the last valid ledger entry and shows a warning on the Stats screen (`tampered` counter). Storage could also be cleared by the OS under memory pressure; there is no backup/export yet (planned).

## 13. Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `npm warn cli … does not support Node.js v26` | harmless; use Node 22 LTS to silence |
| `xcodebuild requires Xcode, but active developer directory is a command line tools instance` | prefix with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`, or `sudo xcode-select -s …` |
| `simctl list runtimes` is empty | no Simulator runtime installed: Xcode → Settings → Components (large download). The app still *builds* for the simulator SDK without it |
| `open -a Simulator` → "Unable to find application named 'Simulator'" | Xcode 27 layout; run from Xcode (⌘R) instead. `simctl` still works headless |
| `simctl io … screenshot` is entirely black | multi-display device (iPhone Duo): add `--display=1` |
| `Incompatible device` creating an iPhone 17/18 simulator | the installed runtime supports only the device types it lists (`simctl list runtimes -j`); use that device |
| `Ad Hoc code signing is not allowed with SDK 'iOS 27.1'` / entitlements need a development certificate | set a signing team in Xcode ([§4c](#4c-as-a-mac-app-my-mac-designed-for-iphone)); not needed for the Simulator |
| `Unable to locate a Java Runtime` | `export JAVA_HOME=/opt/homebrew/opt/openjdk@21` |
| `brew install --cask temurin@21` fails with `sudo: a password is required` | use `brew install openjdk@21` instead |
| Gradle: `SDK location not found` | create `apps/mobile/android/local.properties` with `sdk.dir=/opt/homebrew/share/android-commandlinetools` (the script does this) |
| Gradle fails fetching dependencies | network/mirror problem; see [§14](#14-working-in-iran-tooling-notes) |
| Changes don't appear in the app / PWA shows an old version | cache-first service worker: hard-reload, clear site data, or bump `CACHE` in `public/sw.js` |
| Changes don't appear in the native app | run `npm run cap:sync -w @chaharbarg/mobile` and rebuild from Xcode/Gradle |
| `tsc` error "Object literal may only specify known properties, 'test'" in `vite.config.ts` | vitest bundles its own Vite; test config lives in `vitest.config.ts`, keep it separate |
| e2e: `no chrome` / hangs | set `CHROME=/path/to/chrome`; make sure the dev server is up and nothing else uses port 9333 |
| e2e smoke stuck on a combination prompt | the driver clicks the first combination chip; if you rename `.optchip` or `.hint-line` update `e2e/smoke.mjs` and `src/lib/autopilot.ts` |
| Autopilot text visible in a release build | built with `VITE_AUTOPILOT` set; rebuild clean ([§7](#7-test-hooks-fast-and-the-autopilot)) |
| A recorded `.mov` is 0 bytes | recording still running (data is in the `.sb-…` temp file); stop it with SIGINT, not SIGKILL |
| Status bar overlaps the top-right level badge in the Simulator | seen on iPhone Duo; verify on a normal iPhone. `viewport-fit=cover` plus `env(safe-area-inset-top)` is already used for `.app` padding |

## 14. Working in Iran: tooling notes

Reachability of these from Iranian IPs is **unverified** (see [research.md](research.md) §4); plan around it:
- Commit `package-lock.json` (done). Mirror or vendor npm packages if the registry is blocked.
- Android builds pull from Google Maven, Maven Central and `services.gradle.org`. Pre-populate `~/.gradle` on a machine with access and copy it, or configure a mirror in `android/build.gradle` / `settings.gradle`.
- iOS builds resolve Capacitor through Swift Package Manager (`ios/App/CapApp-SPM`); keep the resolved packages cached.
- Do not depend on Google services (Play, Firebase/FCM, Google Fonts). The app already bundles its font and makes no network calls.
- GitHub is available to Iranian developers since 2021 per GitHub's announcement; the app code does not depend on it.
